# Code of conduct

## The short version

Be straight with people and assume they are being straight with you. Argue about
the work, not the person doing it.

## What is expected

- **Disagree with evidence.** This repo is about refusing to invent numbers. The
  same standard applies in a review thread: if you think a figure is wrong, say
  which figure and what the source says instead.
- **Accept a correction without ceremony.** Being wrong about a threshold or a
  crawler name is normal. Fix it and move on.
- **Say what you did not check.** Half the value here is in the caveats. A pull
  request that says "I tested this on Latin text only" is more useful than one
  that implies it tested everything.
- **Assume the other person has context you do not.** Someone working in a market
  or a script you have never used is usually not confused. They are usually
  looking at a real defect.

## What is not

Personal attacks, harassment, discrimination, or sustained disruption. Posting
someone's private information. Deliberately wasting a maintainer's time, which
includes opening pull requests generated wholesale without review.

## Scope

This applies in issues, pull requests, discussions and commit messages, and to
anyone taking part, maintainers included.

## Enforcement

Report a problem by opening a private security advisory on the repository, or by
contacting the maintainer through the address on their GitHub profile. Reports
are read by the maintainer and kept confidential.

Responses run from a request to edit a comment, through a temporary block, to a
permanent ban for repeated or severe conduct. The maintainer will say which
applies and why, rather than acting silently.

## Attribution

This is a plain-language code of conduct rather than an adaptation of the
Contributor Covenant. If you would prefer the Covenant's wording, open an issue
and say so.
